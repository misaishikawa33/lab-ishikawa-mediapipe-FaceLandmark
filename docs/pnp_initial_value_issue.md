# PnPの初期値設定による姿勢推定の問題

今回、マスクなし画像 `face7.jpg` に対して、マスクなし画像 `face1.jpg` から作成した3Dモデルを用いて位置姿勢推定を行ったところ、全対応点を使用した場合にモデルが極端に小さく描画される問題が発生した。

この問題は、MediaPipe FaceMeshのランドマーク検出精度が低いことが原因ではなく、PnPの初期値設定が原因であった。

PnPは、3Dモデル上の点と画像上の2Dランドマーク点の対応から、カメラに対するモデルの位置と姿勢を推定する処理である。つまり、3Dモデルを画像上に投影したときに、検出された2Dランドマークにできるだけ重なるような回転 `R` と並進 `t` を求める。

修正前の実装では、PnPを毎回以下の固定初期値から開始していた。

```python
rvec = [0, 0, 0]
tvec = [0, 0, 200]
useExtrinsicGuess = True
flags = SOLVEPNP_ITERATIVE
```

これは、モデルがほぼ正面を向いており、カメラの近くにあるという仮定から探索を開始することを意味する。

しかし、横を向いた顔や全対応点を使用する場合、この初期値は実際の姿勢から大きく離れていることがある。`SOLVEPNP_ITERATIVE` は、与えられた初期値から少しずつ誤差を小さくする方法であるため、初期値が悪いと、本来の正しい解ではなく、途中の「それっぽいが間違った解」に収束してしまうことがある。

今回の `face7.jpg` では、修正前の全対応点PnPにより、以下のような結果になっていた。

```text
yaw = 15.75度
t_z = -4182
平均再投影誤差 = 約36px
```

`t_z` の絶対値が非常に大きいため、PnPはモデルをカメラから遠い位置にあると推定していた。その結果、画像上に投影されるモデルが極端に小さくなった。

一方、目元対応点のみを使用した場合は、固定初期値でも比較的安定していた。目元はマスクで隠れにくく、表情や輪郭変化の影響も受けにくいため、PnPが正しい解に収束しやすかったと考えられる。

修正後は、固定初期値から直接 `SOLVEPNP_ITERATIVE` を実行するのではなく、以下の2段階でPnPを行うようにした。

```text
1. SQPNPまたはEPNPで、おおまかな姿勢を自動で求める。
2. その結果を初期値として、SOLVEPNP_ITERATIVEで細かく調整する。
```

これにより、PnPが正解に近い位置から探索を開始できるようになった。

修正後の `face7.jpg` における全対応点PnPの結果は以下のようになった。

```text
yaw = 27.92度
t_z = -1285
平均再投影誤差 = 約2.49px
```

目元対応点のみを使用した場合の結果は以下である。

```text
yaw = 27.72度
t_z = -1299
平均再投影誤差 = 約2.52px
```

修正後は、全対応点を使用した場合でも目元対応点のみを使用した場合と近い姿勢推定結果になった。したがって、今回の大きなずれは、FaceMeshの検出精度や3D点と2D点の対応ミスではなく、PnPの初期値が不適切だったことによって、誤った解に収束していたことが原因である。

今回の結論は以下である。

```text
MediaPipe FaceMeshの検出精度が原因ではなく、PnPの初期値設定により、全対応点使用時に誤った解へ収束していた。
固定初期値から直接ITERATIVEで解くのではなく、SQPNPまたはEPNPで初期解を求めてからITERATIVEで最適化することで、姿勢推定が安定した。
```
